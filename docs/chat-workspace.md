# 채팅과 Site의 공통 작품 저장

구현: Sites D1의 계정별 작품 저장과 /mcp 도구. 운영 반영·앱 연결 검증은 배포 결과를 별도로 확인합니다.

## 사용 흐름

1. Site에서 ChatGPT로 로그인하고 브라우저 작품을 계정에 저장합니다. 기존 로컬 작품은 남습니다.
2. ChatGPT에서 Story Studio 플러그인을 연결한 뒤 “내 작품을 찾아 두 번째 컷을 수정해줘”라고 요청합니다.
3. 도구는 사용자 본인의 DB 작품만 읽고 변경합니다. Site는 새로고침 또는 화면이 열린 동안 15초 간격으로 변경을 확인합니다.
4. Site에서 수정한 계정 작품은 자동 저장됩니다. 동시 수정은 저장 버전 충돌로 중단하며, 화면의 변경을 내보내거나 새 작품으로 보관할 수 있습니다.

## 저장 계약

작품의 기존 .story 모델을 document_json으로 보존합니다. Story 판·Comic 판·Plan 기준 판과 DB 저장 버전은 역할이 다릅니다. 소유자는 Sites가 제공하는 사용자 ID로 결정하며 클라이언트가 지정하지 못합니다. 텍스트와 이미지 내장 데이터를 합쳐 작품당 1.5MB 이하입니다. 큰 이미지의 파일 저장은 후속 미디어 경로로 다룹니다. 사용자 작품은 기본 비공개이며 공개 Site라는 이유로 다른 방문자에게 노출하지 않습니다.

## GPT 도구

- story_list / story_get: 대상 작품과 현재 저장 버전을 먼저 조회
- story_create: 대화에서 합의한 작품 생성, 같은 요청의 중복 생성 방지
- story_update_source: 원본만 변경, 기존 만화·영상 계획 보존
- comic_update_panel: 특정 컷만 변경, 원본과 기존 계획 보존
- video_plan_create: 명시적으로 영상 계획 저장, 실제 제작 실행과 구분

## 손잡고 연결

가입, ChatGPT 로그인, 플러그인 설치·연결 동의, Site 연동 허용 여부, FilmCraft 실행 권한은 별개입니다. 현재 도구 목록에 Sites의 list_plugin_eligibility가 없어 손잡고 커넥터 ID를 선언하지 않았습니다. 가입만으로 Site가 계정에 접근하지 않습니다. 기존 손잡고 프로젝트 링크는 제공합니다. FilmCraft/Remotion의 실제 실행은 연결되어 있지 않습니다.

## 검증

실제 SQL 마이그레이션을 SQLite 엔진에 적용한 테스트에서 소유자 분리·생성 중복 방지·동시 수정 CAS·판 보존·stale·MCP 왕복을 검사합니다. 로컬 미리보기의 ChatGPT 로그인은 Sites 개발 모의 로그인이며 운영 인증 증거가 아닙니다.
